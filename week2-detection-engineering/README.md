# 🛡️ Week 2: Purple Teaming & Detection Engineering

Welcome to the second module of my IT Security Internship sandbox. This week's focus shifts from network hardening to **active threat simulation (Red Team)** and **log-based detection engineering (Blue Team)**.

## 📝 Scenario Overview
In this module, a simulated SSH Brute-Force attack was executed against a legacy target server (Metasploitable) using `Hydra`. Following the attack, forensic evidence (`auth.log`) was securely retrieved via `SCP` bypassing legacy encryption algorithms. 

To automate the forensic analysis, a custom Python-based log parser was developed, mimicking the initial ingestion layer of a SIEM system. Finally, network-level defense mechanisms were established using Snort/Suricata IDS rules to drop future attacks.

## 📂 Directory Contents

* **`log_parser.py`**: A highly optimized Python script engineered to parse large-scale Linux authentication logs.
  * *Features:* Utilizes `collections.defaultdict` for high-performance memory management and `re` (Regex) for precise IP extraction.
* **`threat_report.json`**: The automated output generated by the parser. Formatted in JSON to demonstrate API/SIEM integration readiness.
* **`my_custom_snort_rules.rules`**: A set of custom Detection Engineering signatures.
  * *Features:* Includes direct IP blocking and behavioral analysis (rate-limiting SSH connection attempts to detect automated brute-forcing).

## 🛠️ Technical Highlights

- **Secure Operations:** Managed `HostKeyAlgorithms` and `PubkeyAcceptedKeyTypes` to facilitate SSH/SCP connections to legacy infrastructure.
- **Big Data Approach in Python:** The log parser reads files line-by-line (generator pattern) rather than loading the entire file into RAM (`.readlines()`), ensuring scalability for massive log files.
- **Threat Hunting:** Applied threshold-based Detection Engineering (Rate Limiting) in Snort to catch attackers based on behavioral velocity rather than static signatures.
